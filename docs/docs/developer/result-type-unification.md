# Unifying extension result types (Phase 2b, unpack)

## The problem

Every value that crosses the extension boundary exists in **two** Rust type
universes generated from the same WIT:

- **host** — `kani_core::wasm::kani::extension::types::*` (`wasmtime::component::bindgen!`)
- **guest** — `kani_shared::wit_types::*` (`wit_bindgen::generate!`)

`kani_shared::types::*` is a *third* set — the app's richer domain model
(`authors: Vec<NamedItem>`, `download_status`, …) — not a mirror of the WIT
records. So a shared `unpack_*` had nothing common to *produce*.

## The lever: `wit_types` is already dual-target

`kani_shared::wit_types` is generated by `wit_bindgen` under **both** the `host`
and guest builds (the `host` variant just adds serde derives for the JSON cache).
So it compiles host-side *and* guest-side, distinct from the wasmtime types but
usable as the **shared** representation:

- shared `unpack_*<T: JsonRows>` produces `kani_shared::wit_types::*`;
- the **guest** (codegen, 2c) uses it directly — zero conversion;
- the **host** interpreted `YamlSource` converts `wit_types → wasmtime` at its
  return boundary — ~8 mechanical `From` impls in `kani-core` (where the wasmtime
  types are local, so the orphan rule is satisfied).

No new type family, no wasmtime derives leaking into `kani-shared`.

## Scope of this change (Category A only)

1. **kani-shared** — generic `unpack_manga_list` / `unpack_manga_info` /
   `unpack_chapter_list` / `unpack_pages` over `JsonRows`, returning
   `Result<wit_types::…, ExtensionError>` (the `Result` fixes Group F — malformed
   input becomes an error, not a silent default). Needs guest-safe `has_next_page`
   / `total_pages` spec enums.
2. **kani-core** — `impl From<kani_shared::wit_types::X> for wasmtime X` for the
   9 Category-A types (+ the `types::MangaStatus → wasmtime MangaStatus` hop).
3. **kani-app** — `YamlSource` unpack sites call the shared `unpack_*`, then
   `.into()` to the wasmtime types `SourceBackend` returns. Delete the duplicated
   interpreted `unpack_*`.
4. Verify against `yaml_unification_tests` + `yaml_source_tests` +
   `wasm_conformance_tests`.

## Deliberately out of scope (follow-ons)

- **2c** — invert codegen to emit a spec + `unpack_*` call (guest uses `wit_types`
  natively). Churns every `-gen` extension + snapshots.
- **Category B/C** — filters already have `FilterState`/`ActiveFilter`
  conversions; preferences are declaration-only. Not on the unpack path.
- The 8 `serde_json::from_str::<wit_types::…>` sites already use `wit_types`, so
  they align for free once the interpreter also speaks `wit_types` internally.
